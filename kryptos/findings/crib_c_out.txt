A1.  DOES THE QUOTED INDEX AGREE WITH THE QUOTED CIPHERTEXT?
==============================================================================
The 2010 release states two independent facts about the same window:
an index range AND the letters found there.  A convention is admissible
only if it makes both true at once.  Same test applied to all four cribs
(for the three whose ciphertext string was supplied by the community
rather than the release, this is a consistency check on the community's
read-off, not on Sanborn).

convention                                                 NYPVTT      MZFPK       QQPRNGKSS   FLRV      
---------------------------------------------------------------------------------------------------------
K4, 1-indexed (the standard assumption)                    NYPVTT      MZFPK       QQPRNGKSS   FLRV         ALL MATCH
K4, 0-indexed                                              YPVTTM      ZFPKW       QPRNGKSSO   LRVQ         
'?'+K4, 1-indexed (task c: the K3 question mark counted)   BNYPVT      TMZFP       VQQPRNGKS   WFLR         
'?'+K4, 0-indexed                                          NYPVTT      MZFPK       QQPRNGKSS   FLRV         ALL MATCH
K4 counted from the END, 1-indexed                         SSKGNR      PQQVR       FZMTTVPYN   GWKP         
whole left panel incl. '?', 1-indexed                      VFPJUD      EEHZW       HGNFIVJYQ   KRNS         
whole left panel, letters only, 1-indexed                  VFPJUD      EEHZW       HGNFIVJYQ   KRNS         
last 4 panel rows as carved (= K4), 1-indexed              WTQSJQ      SSEKZ       W?OBKRUOX   VDOH         
final panel row only (31 chars), 1-indexed                 --off--     --off--     --off--     UHUA         

  conventions under which all four quoted (index, ciphertext) pairs hold: 2
    -> K4, 1-indexed (the standard assumption)
    -> '?'+K4, 0-indexed

  CONCLUSION: the quoted index numbers and the quoted/derived ciphertext
  strings are mutually confirming.  Exactly two of the nine conventions
  satisfy them, and those two are the SAME map -- prefixing the '?' and
  switching to 0-indexing are inverse shifts that cancel.  So there is a
  unique admissible reading, and it is the one this repo already uses.

  In particular the task-(c) hypothesis -- that Sanborn 1-indexed over a
  string that begins with the '?' ending K3 -- is refuted by the 2010
  release's own words: under that convention positions 64-69 read BNYPVT,
  not NYPVTT.  The same convention puts CLOCK over TMZFP, NORTHEAST over
  VQQPRNGKS and EAST over WFLR.

A2.  WHERE ELSE COULD EACH QUOTED CIPHERTEXT STRING SIT?
==============================================================================
If a quoted ciphertext string occurs exactly once in K4 then the string
pins the window by itself and the index number is redundant -- an
off-by-one in the reporting could not move the crib.

  BERLIN    ct=NYPVTT     occurrences in K4 (1-indexed starts): [64]         | in the whole 865-letter panel: [832]
  CLOCK     ct=MZFPK      occurrences in K4 (1-indexed starts): [70]         | in the whole 865-letter panel: [838]
  NORTHEAST ct=QQPRNGKSS  occurrences in K4 (1-indexed starts): [26]         | in the whole 865-letter panel: [794]
  EAST      ct=FLRV       occurrences in K4 (1-indexed starts): [22]         | in the whole 865-letter panel: [790]

  Every quoted string is unique inside K4.  For BERLIN the string was
  published by Sanborn himself, so BERLIN's window is nailed down by two
  independent statements and is immune to a reporting off-by-one.
  FLRV, MZFPK and QQPRNGKSS were read off the published layout by the
  community, so for them uniqueness only says the community's read-off is
  self-consistent with the index it was read from.

  Distance to the nearest alternative placement (how far a crib would have
  to slide before its ciphertext letters could repeat):  no repeats exist,
  so any slide changes the ciphertext letters and therefore changes all 24
  (ct, pt) pairs.  That is what crib_b_shifts.py then tests directly.

A5.  WHAT SURVIVES AS AN ASSUMPTION, AND WHAT DOES NOT
==============================================================================
  BERLIN 64-69
      provenance : index AND ciphertext letters both stated by Sanborn via the NYT, 2010
      strength   : FIRM -- two independent statements agree; also restated by Sanborn in person (Elonka's March 2019 lunch notes: 'BERLIN is plaintext that starts at exactly the 64th character')

  CLOCK 70-74
      provenance : index stated by the NYT 2014 ('those in the 70th through 74th position'); ciphertext MZFPK not quoted in the article text
      strength   : FIRM on the index; the 74th letter being K in both plaintext and ciphertext was called out publicly, which independently confirms the alignment of that one position

  NORTHEAST 26-34
      provenance : index stated by the NYT 2020; ciphertext QQPRNGKSS a community read-off
      strength   : FIRM on the index, one source only

  EAST 22-25
      provenance : no index published by Sanborn in words -- released as an IMAGE of the K4 layout to individual correspondents in April 2020, surfaced August 2020
      strength   : WEAKEST.  rumkin.com/reference/kryptos/k4/ records the doubt explicitly: 'It is possible that the first EAST in the plain text isn't correct. Sanborn did confirm it, but it's possible that it was confirmed out of hand as opposed to being intentional.'  Two incompatible provenance stories circulate: (i) Sanborn sent a layout image unprompted [Schwartz, Intel Today], (ii) a solver asked whether EASTNORTHEAST sat at a specific location and Sanborn agreed [rumkin]

  The practical consequence: an off-by-one, if it exists anywhere, is far
  likelier in the EAST/NORTHEAST block than in BERLIN/CLOCK.  That is the
  asymmetric hypothesis crib_b_shifts.py section B2 tests directly (each
  phrase block slid independently by -3..+3) and crib_e_ptct.py extends to
  a free slide of the EASTNORTHEAST block alone.
