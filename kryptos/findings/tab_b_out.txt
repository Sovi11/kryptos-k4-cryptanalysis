# (b) The tableau as a key TABLE: an exact, exhaustive elimination

Null calibration: for a random 24-letter key stream the best-over-26-rotations crib
match has mean 3.25; P(>=6) <= 0.00622, P(>=7) <= 0.000628, P(>=8) <= 5.26e-05, P(>=9) <= 3.7e-06.

## B0. The collapse theorem

Carved body (labels stripped), 26 rows of widths [30, 31]:
  cells where carved != KEYED[(row+col) mod 26] : 0

The anomalous extra L is at body row 13 (label N), column 30 (0-indexed).
  KEYED[(13+30) mod 26] = KEYED[17] = 'L' ; carved = 'L'
  So the extra L is not a WRONG letter -- it is the RIGHT letter in an extra
  column.  The carver continued the row's own rotation one step too far.  This is
  what a miscount looks like and not what a planted signal looks like, and it
  means the carved body and the ideal body are the SAME function of (row, col).

Cells that are NOT that function: the 26 row labels (they are the PLAIN alphabet,
  not the keyed one -- 25 of the 26 differ from KEYED[row]; only label Z coincides)
  and the 2 header/footer rows (plain A-Z + ABCD).  Those are handled in B4.

CONSEQUENCE, and it is the main structural result of this task: for any lookup
path through the tableau body, key_i = KEYED[(row_i + col_i) mod 26].  The two
coordinates are not independent sources of key material -- only their sum matters.
A 26x30 table of 780 cells therefore carries exactly 26 distinct key values, i.e.
log2(26) = 4.7 bits per position, the same as a bare shift.  'Looking the key up in
the tableau' is arithmetically identical to 'adding two position functions mod 26'.

## B2. The FULL affine lookup family, solved exactly

Model: row_i = (r0 + p*i) mod mr, col_i = (c0 + q*i) mod mc, key_i =
KEYED[(row_i + col_i + t) mod 26] by B0.  Free: mr, p, r0, mc, q, c0, t, the combo.

  row parameter triples (mr<=28): 7,714
  col parameter triples (mc<=32): 11,440
  coordinate models: 7,714 x 11,440 = 88,248,160
  x 24 combos x 26 key rotations = 55,066,851,840 trials
  expected 24/24 by chance: 55,066,851,840 * 26^-24 = 6.05e-24

Solved by hash join, not enumeration.  The crib condition is
  PLAINidx_or_KEYEDidx( KEYED[(a_j + b_j + t) mod 26] ) = req_j + rot   for all j,
which for each of the 26 candidate rot values inverts to a required sum vector
v_j, and the condition becomes (a_j - v_j) + b_j = const -- separable in the row
and column parameters, hence an exact O(nrow + ncol) join per (combo, rot).

  hash join complete in 1.0s ; verified 24/24 solutions: 0 ; expected 6.05e-24
    NONE.  The entire affine lookup family is eliminated, exactly, not sampled.

  trials 1,238,016 ; best 9/24 at ((1, 2), (-2, 1), 22, 28, 'vigenere/pt=plain/ct=keyed/key=plain', 25) ; P(>=9) <= 3.7e-06 ; expected 24/24 3.53e-27

A genuine non-repeating knight's TOUR is not testable as a family: the number of
open tours on a 26x30 board is astronomically large and no canonical one is named
by the sculpture, so a 'tour' hypothesis has more free parameters than the 97
letters it would explain.  It is excluded on parsimony, not by search, and this
report says so rather than pretending to have covered it.
